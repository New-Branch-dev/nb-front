## 🌳 Branch Strategy

#### 본 프로젝트는 기능 개발과 버그 수정을 분리하여 브랜치를 운영합니다.

### 📌 브랜치 구조

- main : 배포 가능한 안정 브랜치
- dev : 배포 전 통합 및 검증을 위한 브랜치
- feat/\* : 기능 개발 브랜치
- fix/\* : 버그 수정 브랜치

### ✅ 브랜치 생성 규칙

#### 1. 기능 개발

feat/기능이름

예시:

feat/login
feat/calendar-ui

#### 2. 버그 수정

fix/이슈내용

예시:
fix/api-response-bug

### 🔀 작업 흐름

1. main 브랜치에서 새로운 브랜치 생성
2. 기능 또는 버그 작업 진행
3. 작업 완료 후 PR 생성
4. 코드 리뷰 후 main 브랜치로 병합

### 💡 브랜치 네이밍 규칙

소문자 사용
단어 구분은 - 사용
명확한 의미 전달
